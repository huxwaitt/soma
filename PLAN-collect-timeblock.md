# Plan — collect-information and time-block (administrator 0.3.0)

Two features on top of the 0.2.0 wiki. Names below were confirmed by the user and are fixed.

## 0. Research verdict — Teams

No robust, Windows-proven MCP server for the local Teams client exists. Graph-based servers (Microsoft "Work IQ Teams", floriscornel/teams-mcp, Softeria ms-365-mcp-server) need an Entra app registration and admin consent, which an IT-owned tenant will not give. The local-cache approach (KamorionLabs/msteams-local-mcp, MIT, macOS-built, "Windows untested", 0 stars) is the right idea: the new Teams client is a WebView2 app that keeps recent conversations in an IndexedDB (Chromium LevelDB, V8-serialised values) under
`%LOCALAPPDATA%\Packages\MSTeams_8wekyb3d8bbwe\LocalCache\Microsoft\MSTeams\EBWebView\<profile>\IndexedDB\https_teams.microsoft.com_0.indexeddb.leveldb`.
`ccl_chromium_reader` (MIT, git-only, installs on this machine: 0.3.18 + ccl-simplesnappy + zstd) decodes it. The schema (Teams 2.x, 2026): one database per (tenant, user) named `Teams:<manager>:react-web-client:<tenantId>:<userObjectId>:<locale>`; messages in `Teams:replychain-manager:…` → store `replychains` → record `{conversationId, replyChainId, messageMap: {id: {id, content (HTML), imDisplayName "Name (Org)", from "8:orgid:<guid>", originalArrivalTime | composetime (ISO UTC), messageType "Text" | "RichText/Html" | system types, isSentByCurrentUser?}}}`; chat metadata in `Teams:conversation-manager:…` → store `conversations` → `{id, type, threadProperties.topic, members[{mri, displayName}], lastMessageTimeUtc, lastMessage}`. The running client locks the files: copy the folder to a temp dir, read the copy. Only what the client has synced is there (recent history), no meeting transcripts (those stay on the Copilot-prompt path), and the schema can drift with Teams updates.

Decision: a third server in the user's repo, `local-ms-teams`, read-only, no Graph, optional extra `teams`. Schema mapping follows msteams-local-mcp (MIT, credited in the module docstring); code is our own. This PC has the Teams package but no signed-in profile, so the LevelDB layer is tested through a stub and gets its first real run on the laptop with v0.6.

## 2. local-ms-teams server (`src/local_ms_teams/`)

Files: `__init__.py`, `__main__.py`, `entrypoint.py` (same shape as `administrator_vault`), `cache.py`, `records.py`, `server.py`.

- `cache.py`: `find_cache()` — env `LOCAL_MS_TEAMS_LEVELDB` first, else the Windows glob `%LOCALAPPDATA%/Packages/MSTeams_*/LocalCache/Microsoft/MSTeams/EBWebView/*/IndexedDB/https_teams.microsoft.com_0.indexeddb.leveldb` (macOS glob kept for completeness). `Snapshot` = decoded `accounts`, `conversations`, `messages` as plain dicts plus `taken_at`, `path`, `skipped`. `take_snapshot(path)` copies the `.leveldb` folder (and the sibling `.blob` folder when present) to a temp dir, opens `WrappedIndexDB(leveldb_dir, blob_dir)`, walks the stores, deletes the temp dir. `ccl_chromium_reader` is imported inside the function so the server starts without the extra; `reader_installed` is reported by `teams_status`. A module-level snapshot is reused for `LOCAL_MS_TEAMS_SNAPSHOT_TTL` seconds (default 300) so one collect run copies the cache once; `refresh=true` on any tool forces a new copy.
- `records.py` (pure, fixture-tested): `parse_replychain(value, account) -> list[message]`, `parse_conversation(value, account) -> conversation | None`, `strip_html`, `to_local_iso(ts)` (Teams ISO UTC or epoch ms → local ISO with offset, as Outlook tools return), `sender_name("Jane Doe (ACME)") -> ("Jane Doe", "ACME")`, `chat_title(conversation, self_mri)` (topic, else member display names minus self joined with ", ", else the last sender), `is_system(message)` (messageType outside Text / RichText/Html, or empty text). Message dict: `id, chat_id, reply_chain_id, time, sender, sender_org, sender_mri, is_self, text, type`. Conversation dict: `id, title, type (chat | group | channel | meeting from `type` / threadProperties), members [{name, mri}], last_time, account`.
- `server.py` (FastMCP, `_guard` like the vault server, all tools `readOnlyHint: true`, `response_format="json"` default because the plugin reads JSON):
  - `teams_status(refresh=false)` → `{reader_installed, cache_found, path, accounts: [{key, label}], chats, messages, oldest, newest, snapshot_taken, skipped, hint}`; `hint` is the one-line fix when something is missing ("install the `teams` extra: `uv sync --extra teams` in the checkout, then restart Claude Code" / "sign in to the new Teams client once on this machine").
  - `teams_list_chats(since=None, until=None, limit=30, include_messages=false, per_chat=20, max_chars=300, account=None, fields=None, refresh=false)` → chats with a message in the window, newest activity first: `{id, title, type, members, count, last_time, last_sender, preview}` plus, with `include_messages`, `messages[]` oldest-first capped at `per_chat` (`truncated: n` when cut). Top-level `{chats, total_messages, capped}`.
  - `teams_read_chat(chat_id, since=None, until=None, limit=100, max_chars=600, fields=None, refresh=false)` → `{chat: {...}, messages: [...] oldest-first, truncated}`.
  - `teams_search(query, since=None, limit=30, max_chars=300, account=None, refresh=false)` → substring match on text and sender, newest first.
  - `fields=[...]` filter as the other servers; `since`/`until` are local ISO strings compared after conversion.
- `pyproject.toml`: script `local-ms-teams = "local_ms_teams.entrypoint:main"`; extra `teams = ["ccl_chromium_reader @ git+https://github.com/cclgroupltd/ccl_chromium_reader@master"]`; package found automatically.
- Tests `tests/test_teams.py`: fixtures in `tests/fixtures/teams/*.json` (a replychain record with three messages incl. one system message and one HTML body, a conversation record with topic, one 1:1 without topic); `find_cache` with a temp tree and the env override; `take_snapshot` with a stub `WrappedIndexDB` injected through a module attribute; each tool against a stub snapshot (windowing, caps, `truncated`, `fields`); `teams_status` without the reader and without a cache.

## 3. Vault server additions (`administrator_vault`)

1. `notes.py`: type `chat` → folder `Teams`, required `type, source, chat_id, chat_title, date, account, members, record_id, messages, first, last, created_by`, date key `date`, identity `{chat_id, date}`; `FOLDERS += "Teams", "Time-blocks"`; `FILES += "Priorities.md"`; type `time-block` → folder `Time-blocks`, required `type, source, week, start, end, planned, created_by`, identity `{week}`; `REPLACEABLE_KEYS += messages, last, planned`. Filenames: `Teams/<date> <slug(chat_title)>.md`, `Time-blocks/<week>.md`.
2. `workflows.save_chat(chat, messages, self_names, created_by)` → `vault_save_chat`: writes or extends the day's chat record. `record_id = "<chat_id>|<date>"`. Body: `# <title> — <date>`, `**Members:** …`, `## Messages` with `- HH:MM **Sender**: text <!-- id: <message id> -->`, one per message, oldest first. A second call the same day appends only messages whose ids are not in the file (under `## Update <ISO>` as the other records do) and moves `messages` / `last` forward. Senders that match a person page by name or alias get a Records line and `last_contact` (`wiki.record_person` path with the page's email); senders with no page are returned in `unknown_people[]` (no page is created without an address). Returns `{path, action, added, skipped_duplicates, people: [{name, page}], unknown_people}`.
3. `wiki._record_info`: kind `chat` → `day = date`, `src = record_id`, summary = first message line. `_record_src_id` reads `record_id` first. `wiki_lint.uningested_records` and `_record_day` include `chat`.
4. `vault_collect_sources(action="read" | "advance", source=None, at=None, now=None)`: file `Wiki/_cache/collect.json` `{teams, outlook, notes}` (local ISO). `read` → `{stamps: {...}, age_hours: {...}, ask: bool (any stamp older than 24 h or missing), default_since: <oldest stamp, else today 00:00>, last_collected: "<Thu 21 Aug 18:10>"}`; `advance` sets `source` (or all) to `at` (refused with `older-than-stamp` when earlier than the current one).
5. `vault_changed_notes(since, folders=None, max_chars=1200, limit=20)`: notes under `Administrator/Meetings`, `Emails`, `Daily`, `Weekly` and the vault-relative folders in `Preferences.md: collect_folders` (read-only outside `Administrator/`; `Wiki/`, `Attachments/`, `_views/`, `_backup/` always skipped) modified after `since`, oldest first: `{path, type, modified, ingested (wiki key present), excerpt (last `## Update` section when there is one, else the body, cut at max_chars), truncated}` plus `{count, capped}`.
6. `store.preferences_template`: new keys with one-line explanations — `peak_hours: ["09:00-12:00"]`, `focus_block_minutes: 90`, `focus_blocks_per_day: 2`, `admin_blocks_per_day: 2`, `admin_block_minutes: 45`, `slack_share: 0.2`, `collect_folders: []`. `priorities_template(created_by)`: frontmatter `type: priorities`, `source: administrator`; body explains the file and holds `## Priorities` with `1. (your first priority — a topic page link such as [[Wiki/Topics/acme-supplier-contract]] or plain words)`. Created by `vault_init`, never rewritten. `store.read_preferences()` (frontmatter with defaults filled in, `missing[]` listed) shared by the planner and `vault_changed_notes`.
7. `timeblock.py`:
   - `plan(week, events, today, preferences, priorities)` → `vault_time_block_plan(week, events, today=None)`. Priorities = numbered lines of `Priorities.md` (link target or text) followed by active wiki topics with a `due` within 30 days or open items, not already named (from the index frontmatter). Per working day from `today` on: work window minus events ± `buffer_minutes` minus `no_meeting_blocks`; existing `[Focus]` / `[Admin]` appointments are kept and reported as `existing`. Budget rule: bookable minutes = `(1 − slack_share) × work minutes − meeting minutes`; nothing is booked when that is ≤ 0 and the day is listed under `skipped_days` with the reason. Focus blocks: up to `focus_blocks_per_day`, each ≥ `focus_block_minutes`, the largest free interval inside `peak_hours` first, then the largest outside; priorities assigned in rank order across the week with rank 1 taking every other block. Admin blocks: up to `admin_blocks_per_day` of `admin_block_minutes` outside peak hours, subject `[Admin] Email and small tasks`, one before and one after lunch when possible. Output `{week, priorities: [{rank, name, page}], days: [{date, work_minutes, meeting_minutes, bookable_minutes, slack_minutes, blocks: [{start, end, minutes, kind, subject, priority, existing}]}], totals: {focus_minutes, admin_minutes, slack_share_kept}, unplaced: [...], skipped_days: [{date, reason}], preferences_used, missing_keys}`. Deterministic, no clock reads.
   - `write(week, blocks, created_by)` → `vault_time_block_write`: `blocks` = the plan blocks plus the create results (`entry_id`, `occurrence_key`); writes `Time-blocks/<week>.md` with `## Plan` table (`Day | Start | End | Kind | Subject | Priority` + `<!-- occurrence_key: … -->`), empty `## Held` table (`Day | Block | Result | Note`), `## Notes`. Upsert: a re-plan appends under `## Update`.
   - `audit(week, events, held_rows)` → `vault_time_audit(week, events)`: events classified `focus` (`[Focus]`), `admin` (`[Admin]`), `meeting` (attendees > 0 or `is_meeting`), `other`; all-day skipped; `## Held` rows of the week's note override: `skipped` blocks count as unplanned, `moved` keeps the minutes. Returns `{week, hours: {meeting, focus, admin, other, unplanned}, work_hours, shares, per_priority: [{name, planned_hours, held_hours}], blocks: {planned, held, moved, skipped, unanswered}, lines: [...]}` with `lines` ready for `## Time`.
8. `server.py`: 6 new tools (31 total). `CREATED_BY = "administrator/0.3.0"`.
9. Tests: `test_chat.py` (save, re-run dedupe, person match), `test_collect.py` (stamps, ask rule, changed notes incl. `collect_folders` and the skip list), `test_timeblock.py` (planner against a fixed week with meetings, slack refusal, peak placement, existing blocks, priorities from file and wiki; write; audit with held rows), `_record_info` on a chat record, lint check 11 with a chat record.

## 5. Plugin (administrator 0.3.0)

- `skills/collect-information/SKILL.md` (≤ 120 lines) + `references/examples.md`; `commands/collect-information.md`. Steps: load skills; `vault_collect_sources("read")` → when `ask`, one question "Last collected: <…>. Collect since then, or just today?" and stop the turn; sources in order Teams (`teams_list_chats(since, include_messages=true, per_chat=20, max_chars=300, limit=15)`; skip when no `teams_*` tools or `cache_found` false, say so in one line), Outlook (`outlook_list_mails(folder="inbox", since, fields=[...], preview_chars=80, limit=50)` and `folder="sent"`; `vault_wiki_match` on subject + sender per mail; `outlook_get_mail` on at most 8 with a match or a candidate; `vault_save_email` for each of those), notes (`vault_changed_notes(since)`); records first (`vault_save_chat` per chat with messages), then ingest oldest-first by timestamp with the `wiki` skill's steps; **before any ingest**, show the proposed changes as short bullets grouped by page, plus Review items expected, and wait for a yes (strike lines on request); then the `vault_wiki_ingest` calls, `vault_collect_sources("advance", at=<now>)` per source that was read; then the time-block question for today's `[Focus]` / `[Admin]` appointments ("held / moved / skipped?") recorded with `vault_append_row(<Time-blocks note>, "Held", …, dedupe_key=<occurrence_key>)`. Report: counts per source, pages changed with links, Review count, "Last collected" now. Caps stated in the skill; nothing in Outlook or Teams is changed.
- `skills/time-block/SKILL.md` (≤ 120 lines) + `references/method.md` (the five findings in ≤ 20 lines, with the numbers) + `references/examples.md`; `commands/time-block.md`. Steps: preferences and `Priorities.md` (`vault_read` once; if the list is empty ask for 3 priorities in one question); last week's audit first (`outlook_list_events` for last week with `fields=["subject","start","end","all_day","attendee_count","is_meeting","occurrence_key","busy_status"]`, `vault_time_audit`) shown in 3 lines; `outlook_list_events` for the target week (same fields + `entry_id`); `vault_time_block_plan`; show the week as one line per day; one question "Book these N blocks? They are appointments without attendees — nothing is sent to anyone."; on yes one `outlook_create_event` per block (`show_as="busy"`, `categories="Administrator"`, `reminder_minutes=0`, body `Planned by administrator on <date> for <priority>`), then `vault_time_block_write`; "re-plan" removes nothing — existing blocks stay, the user deletes in Outlook. Report with the note link.
- `commands/weekly.md`, `skills/review/SKILL.md`: `## Time` from `vault_time_audit` (needs the week's events: one `outlook_list_events` for the review week with the audit fields) between `## People going quiet` and `## Wiki`; `vault.md` weekly section updated.
- `commands/daily.md`: agenda lines mark `[Focus]` / `[Admin]`; a meeting overlapping a block → watch-out bullet and an offer to move the block (`outlook_update_event` on the block after a yes; no attendees, nothing sent).
- `skills/schedule/SKILL.md` + `commands/free.md`: `max_meetings_per_day` ignores `[Focus]` / `[Admin]` subjects; `references/preferences.md` gains the new keys.
- `commands/setup.md`: third server check (`teams_*` tools; missing → one line with the `uv sync --extra teams` hint, not a failure), `teams_status` line, `Priorities.md` in the created list, link to `Priorities.md` too.
- `skills/administrator/SKILL.md`: two table rows, trigger phrases, vault tree (`Teams/`, `Time-blocks/`, `Priorities.md`), tool lists; `references/vault.md`: chat note, time-block note, Priorities.md; `skills/wiki/SKILL.md`: chat records (src = `record_id`), collect-information in the ingest list; `plugin.json`: `local-ms-teams` server, version 0.3.0, description; README sections. `created_by` everywhere → `administrator/0.3.0`.

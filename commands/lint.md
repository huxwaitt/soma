# /administrator:lint

Argument (optional): `fix` applies the safe fixes (regenerate the index, recompute code-owned keys, fix section order, move ticked open items to History, turn dangling links in code-owned sections into plain text, set stale topics to `dormant`, write the missing side of a one-way link between two pages, turn an `owner` that is a plain name into a link to that person's page, roll over long History sections and the log). Without it, only the flags (`orphan`, `stale`, `oversized`, `possible-duplicate`) on the pages, the Review lines, the index, one Log line and the report file under `Wiki/_cache/` are written.

Argument given: `$ARGUMENTS`

## Steps

1. Load the `administrator` skill, then the `wiki` skill.
2. `vault_status` once per session; `folders["Wiki"]` false → `vault_init(created_by="administrator/0.4.0")` and mention `/administrator:setup` (it offers the migration of an older vault).
3. One call: `vault_wiki_lint(fix=<true when the argument is "fix", else false>, items=true, created_by="administrator/0.4.0")`. `items=true` is asked for because steps 5, 6 and 7 read checks 10, 12, 17, 18, 19, 20 and 21 out to the user line by line; without it the answer is the counts, the flags and the Review lines alone, and every `items` below is missing. The result: `counts` (one number per check: `dangling`, `orphans`, `frontmatter`, `sections`, `oversized`, `stale`, `due_past`, `open_done`, `duplicates`, `uningested`, `candidates`, `history_over`, `ask_model`, `unconfirmed`, `consistency`, `close`, `thin`, `overdue`, `unanswered`, and `questions` as the text `"<answered>/<asked>"`), `counts["hand_edits"]`, `checks` keyed `"0"`…`"21"` (`checks["0"]` is the pass that reads back what the user changed in Obsidian: `{name: "hand-edits", adopted: [{page, changes}], review, first_run, scanned}`) (each with `name`, its `items` / `pages` / `records` and `fixed` where a fix exists; `checks["10"].items` are the duplicate pairs `{a, b, shared}`, `checks["12"].items` the topic candidates, `checks["14"].ask_model` the pages touched since the last lint whose Facts the model should read for contradictions, `checks["19"].items` = `[{page, id, text, due}]`, the user's own open items past their due date, each with a Review line "done, reschedule, or drop"; `checks["16"].items` = `[{page, kind: "org-contacts" | "link" | "owner" | "due", …}]`, two pages that disagree — a one-way link or a person's `org` (`other`, `section`, `fixed`), an `owner` no person page carries (`owner`, `other`), or a topic's `due` against a fact naming another day (`due`, `id`, `text`); `checks["17"].items` = `[{page, due, verified, days}]`, projects with nothing new for 90 days; `checks["18"].items` = `[{page, sources, days}]`, pages still on one record after 60 days; `checks["20"]` = `{name: "questions", asked, found, misses: [{question, expected, top: [...]}], unknown: [{question, expected}]}`, the user's own questions from `Wiki/Questions.md` asked of the wiki; `checks["21"].items` = `[{query, times, last}]`, the questions the wiki could not answer at all, each with a Review line), `flagged` (page → flags), `review_added` (the lines), `written` (pages rewritten), and `cache` (the report file). Decision pages are left out of the stale check (7) on purpose. The answer also carries `confirmed_decisions: [<page stems>]` when the user ticked an "unconfirmed decision" line in `Review.md` — the flag is cleared and the line moved to Done; name those pages in one line.
4. **Check 14.** For each stem in `checks["14"].ask_model` (at most 10 per run; say when more were skipped): `vault_wiki_read(path, sections=["facts"])`, read the Facts, and for each pair that cannot both be true send `vault_wiki_apply(path, ops=[{"op": "contest", "id": <the newer one>, "text": <the older text>, "src": <the older fact's src>}], created_by="administrator/0.4.0")`. No pair → nothing. Never supersede or retire from lint; Review lines only.
5. **Check 19.** Read `checks["19"].items` out as they are — one line each, `"<text>" on [[<page>]], due <date>` — and ask what to do with each: done (`{"op": "done", "id": …}`), a new date (`{"op": "reschedule", "id": …, "due": …}`) or drop it, through `vault_wiki_apply(path=<the page>, ops=[…], src="user")`. One question per item, at most 5 per run; no answer leaves the Review line standing.
6. **Proposals** (checks 10, 12, 17, 18 and 21) are questions, not actions. Ask one per item, at most 5 of each kind per run; silence is a no, and a no leaves the Review line standing.
   - 10 "merge A into B?" → on a yes `vault_wiki_merge(keep, drop, created_by="administrator/0.4.0")`.
   - 12 "create topic `<slug>` from N records?" → on a yes `vault_wiki_create(type="topic", title, aliases, lead, summary, facts=[], src=<first record's id>, created_by="administrator/0.4.0")`, then offer to ingest the candidate's records (`/administrator:wiki ingest …`).
   - 17 "`<page>` is due `<date>` and nothing has moved for `<days>` days — close it?" → on a yes `vault_wiki_apply(path=<the page>, ops=[{"op": "status", "value": "closed"}], src="user", created_by="administrator/0.4.0")`. "Still live" → offer `at-risk` or a new `due` instead.
   - 18 "`<page>` still stands on one record after `<days>` days — merge it into another page or retire it?" → merge as in 10, retire with `ops=[{"op": "status", "value": "closed"}]` (a howto or org that is simply quiet stays as it is; say so and move on).
   - 21 — read the question back as it was asked and add how often: "You asked *<question>* <times> times and the wiki had nothing — create a page for it?" On a yes create it as in 12, with the question's own words in the lead, and say which records it should be filled from.
7. **Check 20.** `checks["20"]` is the score of the user's own questions: report `found`/`asked` as one line, then each miss as `"<question>" → expected [[<page>]], came back: <the first three hits>` (at most 5), and each `unknown` line as `"<question>" → [[<page>]] does not exist yet — create it?`. No questions on file (`asked` 0 and `unknown` empty) → one line saying `Wiki/Questions.md` has no questions yet (only the two examples above the list) and that questions written there are checked on every run. Never edit that file: it is the user's.
8. Report: when `checks["0"].adopted` is not empty, one line first naming the pages read back and what changed on them; then one line per check with a count above zero (`<name>: <count>` plus `fixed` when `fix` ran), the Review lines added (verbatim, at most 10), the pages flagged, the un-ingested record count with `/administrator:weekly` as the way to ingest them in batches, the decisions confirmed by a tick, the questions line (`questions <found>/<asked>`, plus `unanswered <n>` when there are any) even when nothing else changed, then `obsidian://open?vault=<vault_name>&file=Administrator/Wiki/Review` when Review grew. Checks with a zero count are left out. No raw JSON. The same counts go on one line in `Wiki/Log.md` on every run, so the trend is readable there. Under the counts, one line for the token calibration from `Wiki/_cache/tokens.json` — one `vault_collect_sources(action="read")` (it only reads; no stamp moves) → `tokens`: "Estimates: collect-information 7 runs, in ×1.2 / out ×0.9; load-history 4 runs, in ×0.8 / out ×1.1". No runs on file for a command → leave it out; none at all → leave the line out.
9. If the host shows the turn's token count, end with `Tokens this turn: <n>`; otherwise say nothing about it.
